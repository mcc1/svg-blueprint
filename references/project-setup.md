# Project setup

One-time setup in the target project, for [`SKILL.md`](../SKILL.md). Paths assume the blueprint folder is `design/blueprint/`; adjust them if it lives elsewhere.

## Version control

| Path | Status | Why |
|---|---|---|
| `inventory.md`, `tokens/`, `flow/`, `components/`, `screens/` | committed | the design itself |
| `guardrails.lock` | committed | every diff to it is a design change the user signs off |
| `shots/` | committed | evidence for step 8; see platforms.md "Capturing at 1x" for keeping it small |
| `_build/clean/` | committed, not locked | visual guardrails compare against it, so CI needs neither Python nor the skill; regenerate it with `build_doc.py` after drawing changes and commit the result |
| `_build/` (everything else), `index.html` | ignored | regenerated by `build_doc.py` |

Add to the project's `.gitignore`:

```text
/design/blueprint/index.html
/design/blueprint/_build/*
!/design/blueprint/_build/clean/
```

## Test harness

Set this up once, before the first unit reaches step 6. Use [platforms.md](platforms.md) for the target platform and what the project already has; ask the user before adding each new dependency.

1. **Test runner** that can run the guardrail folder on its own (for example `tests/guardrails/`).
2. **Capture harness**: a way to show one unit in one state at the reference size and save a 1x screenshot (a component workbench, a debug scene, a snapshot library).
3. **Rasterizer** for `_build/clean/` drawings at the same size (a headless browser, resvg, or the snapshot library's own).
4. **Image comparison** with a tolerance metric (share of differing pixels, or a perceptual difference) and an output image of the difference for step 8.

Done when: the user approved every new dependency, and one trivial visual test (any drawing compared with itself) runs and passes in the runner.

## Commands

Run every `build_doc.py` and `guardrails.py` command from the project root; file arguments and the guardrail paths in `spec.md` are relative to it. Example:

```bash
python <skill>/scripts/guardrails.py lock design/blueprint design/blueprint/components/button/spec.md design/blueprint/components/button/*.svg
```

## Continuous integration

Run the guardrails with the project's normal tests, and add one check that fails the build when a locked file changed or an approved unit is not locked:

```bash
python <skill>/scripts/guardrails.py check design/blueprint
```

When the skill is not available in CI, vendor `scripts/guardrails.py` into the project (it needs only the Python standard library).
